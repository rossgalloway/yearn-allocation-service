Implemented

  • Multicall3: compatible accounting, allocator configuration, and metadata getters are grouped at the exact historical block, up to 50 subcalls per aggregate. Caller-sensitive trigger replay stays direct. Transaction lookups, traces, and bytecode checks use separate RPC methods.
  • Persistent finalized RPC cache: successful historical getters, bytecode, transactions, and traces are stored in Postgres with chain and canonical block hash identity. Refreshes verify chain identity and a saved finalized anchor. Errors, null responses, and unfinalized reads are not retained as successful results.
  • Incremental state reuse: unchanged historical states are reused. Evidence fingerprints include cumulative event history, relevant deployments, and same-block checkpoints; late or corrected evidence invalidates affected states. Incomplete enrichment is retried. The service still scans Envio and assembles the full immutable public projection from those states. It does not yet publish only an appended tail.
  • Bounded materialization: the head is capped to the lower of RPC finality and Envio indexed progress. Pre-vault shared-allocator events remain evidence without causing reads before vault creation. Runs activate atomically after accounting and interval validation; failures retain the prior active run.
  • Coverage: the existing vault configuration enrolls the selected 21 addresses. No new chain adapter or REST route was needed. Public database-backed requests make no RPC calls.

Measured validation

  • A fixed-head yvvbUSDS comparison produced the same seven entries with cached states and forced state reconstruction. Each path needed only three RPC identity/finality checks, with no cache misses. See fixed-head parity evidence.
  • yBOLD's cold backfill issued 121,836 RPC methods; the subsequent warm refresh issued 10, reused 19,884 states, and built 273. All 1,522 common historical entries were unchanged. The heads differ, and the cold counter omits initial guard calls; these are method counts, not provider billing units. See large-vault cache evidence.
  • Consumer validation checks all 21 chart endpoints, current accounting, both pagination directions, older-page isolation, pinned entry details, and provisional/no-store response metadata. See preview validation and per-vault heads.
  • The normal suite passed 98 tests; four Postgres integration tests passed separately. Lint and production build passed. The earlier three-chain Multicall comparison matched direct getter results.

Operational limits

Runs remain provisional until Envio supplies immutable coverage and indexed checkpoints suitable for certified history. Unsupported enrichment stays unavailable rather than zero. Refresh scheduling, bounded retry orchestration, cache retention, and append-only public projection publication remain separate follow-ups. Current refreshes reuse expensive historical evidence and states, while re-evaluating grouping, proposal evidence, intervals, and serialization.

One initial yvWETH-2 run failed a block-identity guard; a subsequent retry passed and activated. USDC cold reconstruction exposed high memory use; raw traces are now reduced in pages of 100, and remaining cold backfills use fresh lower-memory processes. Assignment-changing events are selected once per phase, and per-block events use a lookup map, avoiding repeated full-history scans and sorts. Interrupted runs retain their cache and never activate partial data. Missing or inconsistent RPC evidence never bypasses these guards. No production deployment was performed.
